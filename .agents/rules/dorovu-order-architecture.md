# Dorovu Architecture & Invariants

When working on the Dorovu e-commerce platform, adhere to the following architectural patterns and strict state machines.

## 1. Order Item State Machine
Order items flow through a strict, forward-only linear progression:
`PENDING` -> `ACCEPTED` -> `READY_FOR_PICKUP` -> `SHIPPED` -> `OUT_FOR_DELIVERY` -> `DELIVERED`

- **Rollbacks are NOT allowed.**
- **Cancellations (`CANCELLED`)** are only permitted when the state is `PENDING` or `ACCEPTED`.

## 2. Role-Based Permissions
- **Crafters**: Can only manage early fulfillment. They can transition states to `ACCEPTED` and `READY_FOR_PICKUP`. They interact via action buttons (not dropdowns) in the Crafter Orders UI.
- **Admins**: Handle the "Logistics" phase. They transition states to `SHIPPED`, `OUT_FOR_DELIVERY`, and `DELIVERED` via the dedicated `/admin/logistics` portal.

## 3. Tracking System (`DRV-[UUID]`)
- Tracking numbers are automatically generated by the backend when an item transitions from `PENDING` -> `ACCEPTED`.
- The public tracking interface is located at `/tracking`.
- The admin logistics portal is located at `/admin/logistics`.

## 4. Secure Delivery & Payouts (OTP Flow)
Releasing funds to crafters is strictly tied to the `DELIVERED` state.
- When an Admin marks an item as `OUT_FOR_DELIVERY`, a 6-digit `deliveryOtp` is generated.
- The Buyer views this OTP in their profile/orders UI.
- The Admin must physically collect this PIN from the buyer and enter it into the `/admin/logistics` portal to transition the state to `DELIVERED`.
- The `DELIVERED` transition triggers `AccountingService.releaseFunds` within a Prisma transaction to ensure atomic ledger updates.
